## 一、系统概述

### 1.1 项目背景

当前大模型技术在教育领域的应用面临两大核心挑战：一是大模型在生成专业实操指南时极易产生"幻觉"，输出不符合行业规范的内容；二是"个性化适配"与"专业质量把控"在单一模型架构下难以调和。

本系统采用"多智能体协同决策"技术路线，构建了 6 个具有明确职责分工的 AI Agent，通过"分析—生成—校验—决策"的协同闭环，在 CNC 数控加工单一领域内构建了三级职业阶梯模型（操机工 L1 → 调机工 L2 → 编程师 L3），每个职业方向有独立的技能树、核心知识点和上下文 prompt，学习者画像中选择职业方向+当前水平+技能自评后系统精准诊断盲区。实现了高保真、个性化学习资源的按需生成。

### 1.2 系统目标

- 为不同背景的学习者精准诊断知识盲区，匹配适宜难度
- 基于 RAG 知识库 + 来源溯源，自动生成讲义、实验指导、项目案例和分阶试题
- 通过双视角审核纠偏机制，将知识谬误率控制在 5% 以下
- 根据答题反馈实时调整学习路径，实现自适应学习闭环

### 1.3 技术亮点

1. **双视角审核纠偏机制**：学术审查者 + 工业实践者并行审查，Severity-Weighted 评分，自动修正 + 回归验证
2. **知识溯源体系**：每条知识点标注出处（书名、作者、章节）
3. **苏格拉底式追问导学**：3 轮逐级降级提示，启发学习者自主思考
4. **多领域可迁移架构**：配置驱动的 DomainConfig，添加新领域只需增加配置和知识库
5. **消融实验框架**：有/无审核双工作流对比，量化验证审核机制的谬误降低效果

## 三、多智能体设计

系统共包含 6 个 AI Agent，每个具有明确的职责分工和独立的 LLM 调用能力。

### 3.1 学情诊断 Agent（DiagnosisAgent）

**职责**：根据学习者输入（学历背景、专业方向、工作经验、技能自评、学习目标）构建详细画像，定位知识盲区，匹配适宜难度。

**核心方法**：
- `build_profile(input_data)` — 调用 LLM 构建 JSON 画像，包含知识点评分、盲区列表、整体水平、推荐难度
- `locate_blind_spots(profile, knowledge_map)` — 对照领域知识图谱定位盲区
- `match_difficulty(profile)` — 四档难度判定（beginner / intermediate / advanced / expert）

**难度判定标准**：
| 等级 | 条件 |
|------|------|
| beginner | 零基础，非相关专业，从未接触该领域 |
| intermediate | 有相关基础（相关专业或工作经验），但该领域经验较少 |
| advanced | 丰富经验（3 年以上），能独立完成复杂任务 |
| expert | 领域专家，5 年以上经验，精通高级技术 |

### 3.2 路径规划 Agent（PathPlannerAgent）

**职责**：根据学情诊断结果，为学习者生成个性化多阶段学习路径。

**核心方法**：
- `plan_path(profile, topic)` — 生成 JSON 学习路径，包含阶段、知识点、预估学时、难度、前置依赖、推荐资源类型
- `adjust_path(path, feedback)` — 根据答题正确率动态调整路径（< 60% 降级插入基础阶段，> 90% 进阶到下一阶段）

### 3.3 知识生成 Agent（GenerationAgent）

**职责**：结合 RAG 知识库检索结果，生成三种形态的个性化学习资源，并附知识溯源标注。

**核心方法**：
- `generate_lecture_notes(topic, profile, domain, retry_context)` — 定制化讲义（≥ 800 字）
- `generate_practical_guide(topic, profile, domain, retry_context)` — 实验指导（≥ 600 字）
- `generate_project_case(topic, profile, domain, retry_context)` — 项目案例（≥ 1000 字）

**来源引用规则**：每个知识点必须标注来源信息：
```
[知识点：XXX]
📚 来源：《书名》(作者, 年份) 章节
权威度：★★★★★
```
禁止编造不存在的书名、论文或 URL。知识库无相关信息时标注"[需人工确认来源]"。

### 3.4 审核纠偏 Agent（ReviewAgent）

**职责**：对生成内容进行双视角交叉验证，发现问题后自动修正并验证修正效果。这是系统的核心质量保障机制。

**核心方法**：
- `corrective_review(content, topic)` — 完整审核纠偏流水线：
  1. **双视角并行审查**：学术审查者（概念准确性）+ 工业实践者（操作可行性）
  2. **Severity-Weighted 评分**：critical (-0.15) / minor (-0.05) / suggestion (-0.02)，阈值 0.70
  3. **自动修正**：未通过时调用 LLM 根据审核意见修正内容
  4. **回归验证**：对比修正前后，判定问题是否真正解决

**问题严重度定义**：
| 级别 | 定义 | 扣分 |
|------|------|------|
| critical | 事实性错误、概念定义错误、编造不存在的内容 | -0.15 |
| minor | 表述不精确、推理不严谨、缺乏引用来源 | -0.05 |
| suggestion | 优化建议、风格改进、补充说明 | -0.02 |

### 3.5 试题生成 Agent（QuestionGeneratorAgent）

**职责**：根据学习主题和难度生成三种题型的试题，并经过格式校验。

**题型**：
- 选择题（multiple_choice）：4 选 1，考察领域知识点
- 判断题（true_false）：考察领域概念辨析
- 实操题（practical）：描述领域操作步骤或编程思路

**格式校验**：`_validate_questions()` 纯规则校验，不依赖 LLM，确保选项数量、答案合法性、题型正确性。

### 3.6 决策调度 Agent（DecisionOrchestrator）

**职责**：工作流路由决策 + 学习路径动态调整。

**核心方法**：
- `decide_next(state)` — 审核通过→完成 / 未通过且未超限→重试 / 超限→降级完成（最大 3 次重试）
- `adjust_learning_path(path, feedback_history)` — 基于滑动窗口（最近 5 题）正确率调整难度和阶段

## 四、工作流设计（LangGraph）

### 4.1 状态定义

```python
class AgentState(TypedDict):
    learner_input: dict      # 学习者输入
    topic: str               # 学习主题
    profile: dict            # 诊断画像
    difficulty: str          # 难度等级
    learning_path: dict      # 学习路径
    generated_content: dict  # 生成资源
    review_results: dict     # 审核结果
    question_set: dict       # 试题集
    retry_count: int         # 重试次数
    final_resources: list    # 最终输出
    feedback_history: list   # 反馈历史
    decision_log: list       # 决策日志
```

### 4.2 工作流拓扑

```
                    ┌─────────┐
                    │ analyze │ ① 学情分析
                    └────┬────┘
                         │
                    ┌────▼────┐
                    │plan_path│ ② 路径规划
                    └────┬────┘
                         │
                    ┌────▼────┐
              ┌─────│generate │ ③ 知识生成
              │     └────┬────┘
              │          │
              │  retry  ┌──────────────┐
              └─────────│review_correct│ ③½ 审核纠偏
                        └──────┬───────┘
                               │
                    ┌──────────▼──────────┐
                    │     decide_node      │ ⑥ 决策路由
                    │  complete / retry    │
                    └──────────┬──────────┘
                               │ complete
                        ┌──────▼───────┐
                        │gen_questions │ ⑤ 试题生成
                        └──────┬───────┘
                               │
                        ┌──────▼───────┐
                        │   finalize   │ 最终输出
                        └──────────────┘
```

### 4.3 重试与降级机制

- 最大重试次数：3
- 每次重试时将上一轮审核未通过的问题注入生成 prompt，确保本轮修正
- 超过最大重试次数后走降级流程：保留最后一次生成内容，标注"未通过质量审核，仅供参考"
- 消融实验版本：`run_workflow_no_debate()` 跳过审核纠偏节点，用于对比验证

## 五、知识库设计

### 5.1 知识库架构

```
knowledge-base/
├── cnc_domain/           # CNC 数控加工领域（21 篇）
│   ├── theory/           # 理论知识（8 篇）
│   ├── practice/         # 实操指南（8 篇）
│   └── standards/        # 行业标准（5 篇）
└── (Python 数据分析领域已移除，专注 CNC 职业培训)
```

### 5.2 文档格式

每篇 Markdown 文档包含 YAML 前置元数据：

```yaml
---
title: G 代码基础
source_type: standard
source_name: GB/T 8870
author: 全国数控机床标准化技术委员会
publisher: 中国标准出版社
year: 2019
chapter: 第4章 准备功能 G 代码
---
```

### 5.3 检索流程

1. 文档加载 → YAML 元数据解析 → 递归字符分割（1000 字符/块，200 字符重叠）
2. DashScope text-embedding-v3 嵌入 → ChromaDB 向量存储
3. 查询时相似度搜索返回 top-k 文档 → 格式化后注入 LLM prompt

### 5.4 职业方向配置（CNC 三级职业阶梯）

系统定义了 3 个层级递进的 CNC 职业方向：

```python
@dataclass
class CareerTrackConfig:
    name: str              # 职业中文名称（操机工/调机工/编程师）
    code: str              # 职业代码
    order: int             # 职业层级序号（1→2→3）
    description: str       # 职业描述
    knowledge_base_dir: str  # 知识库目录
    core_topics: list      # 核心主题
    prompt_context: str    # 注入 prompt 的职业上下文
    self_assessment_skills: list  # 技能自评项（8项/职业）
    prerequisite_knowledge: str   # 前置知识要求（支撑层级递进）
```

- 操机工（L1）：零基础准入，负责机床操作、工件装卸、简单检测
- 调机工（L2）：需操机工基础，负责对刀、参数调整、首件检测
- 编程师（L3）：需操机+调机基础，负责编程、CAM、工艺规划

## 十、创新点总结

1. **双视角审核纠偏 + 回归验证**：学术+工业双视角并行审查，Severity-Weighted 评分，自动修正后对比验证，确保修正有效性
2. **知识溯源体系**：每条知识点强制标注来源（书名、作者、年份、章节），禁止编造，支持来源汇总可视化
3. **苏格拉底式 3 轮追问导学**：答错时逐轮降级提示（引导思考→类比启发→直接提示），启发式交互打破单向输入
4. **多领域可迁移架构**：DomainConfig 配置驱动，添加新领域只需增加配置项和知识库目录
5. **消融实验框架**：有/无审核双工作流，量化验证审核机制对谬误率的降低效果（> 50% 降低）
6. **独立谬误检测器**：不依赖 Agent 自评，RAG 知识库独立事实核查，随机抽样 20 条断言逐条比对
7. **Mock 模式**：开发调试零成本，一键切换真实 API
8. **数据跨页面缓存**：前端 `useState` 持久化，页面切换不重复请求

# 权威基准｜数控编程代码与控制器差异

## 适用岗位

适用于需要识读 G/M 代码、编制程序、配置后处理器或审核跨设备程序的学习者。本文的核心不是扩充代码表，而是建立“标准代码、控制器实现、机床厂配置”三层边界。

## 学习目标

1. 知道通用编程代码与具体控制系统实现不是同一层级。
2. 能识别程序中需要查阅厂商手册的专用功能。
3. 能为程序建立控制器、机型、选件和版本标识。

## 权威来源

| 编号 | 来源 | 发布状态 |
|---|---|---|
| [S1] | GB/T 38267-2019《机床数控系统 编程代码》 | 现行，2020 年实施 |
| [S2] | GB/T 40328-2021《工业机械电气设备及系统 数控加工程序编程语言》 | 现行，2022 年实施 |

两项国家标准为程序代码和加工程序语言提供规范基础。[S1][S2] 但实际机床由数控系统、PLC/PMC、机床制造商参数、外围设备和选件共同决定。学习资料必须把共性概念与设备专用行为分开。

## 三层解释模型

### 第一层：标准与通用概念

包括程序段、地址字、准备功能、辅助功能、坐标、插补、进给、主轴、刀具和补偿等共同概念。这一层用于建立术语和程序阅读方法，不直接保证某个代码在所有设备上行为一致。

### 第二层：控制器实现

FANUC、SINUMERIK 等系统可能采用不同的宏程序语法、变量体系、固定循环、刀具数据模型、程序管理方式和选件名称。即使常用运动代码相似，参数格式、模态关系、复位状态和报警条件也可能不同。

### 第三层：机床制造商配置

换刀、卡盘、尾座、托盘、门、排屑器、冷却和机器人接口等动作常由机床厂通过 PLC/PMC 和参数配置。某个 M 代码在一台设备上的含义不能自动推广到另一台设备。机床铭牌、制造商说明书和现场程序规范应作为最终依据。

## 程序头信息建议

经批准的程序至少应能追溯以下信息：

- 适用机床编号、控制器系列和软件版本。
- 后处理器名称、版本和生成日期。
- 零件号、工序号、程序版本、编制与审核人员。
- 坐标系、刀具表、补偿表和夹具版本。
- 必需选件、宏变量或 PLC/PMC 接口说明。
- 仿真、空运行、首件和变更验证记录。

## 专用功能识别清单

看到以下内容时，不应仅凭通用教材判断：宏变量、系统变量、探测循环、多轴坐标变换、动态刀具补偿、高速高精功能、刚性攻丝参数、复合循环、程序传输协议、机床门与夹紧动作、机器人或托盘接口。应转查对应控制器和机床手册。

## 案例

编程人员把一台加工中心的冷却、吹气和夹具 M 代码复制到另一台设备。程序语法检查没有报错，但外围动作与预期不一致。问题不是“代码写错”，而是忽略了第三层机床配置。正确流程是建立目标机床代码表，由设备负责人确认专用 M 功能，再在无工件或安全条件下逐项验证。

## 判定清单

- 是否明确标注了控制器系列与目标机床。
- 是否把标准代码和厂商专用代码分开记录。
- 是否禁止凭相似名称推断宏变量或辅助功能。
- 是否对程序变更执行版本控制和重新验证。
- 是否在自动运行前确认夹紧、门、刀具和坐标状态。

## 练习题

1. 说明数控程序代码的三层解释模型。
2. 为什么辅助功能比基础直线插补更需要机床级验证？
3. 为一段含宏程序、探测和自动夹具动作的程序列出所需资料。
